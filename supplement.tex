\section{Protocol and Information Boundary}
All primary ranking experiments use chronological 70/15/15 splits and
collision-filtered historical negatives.  HRCSR reserves a chronological
suffix of the target-training period for calibration.  The checkpoint-boundary
audit exposes validation-selected, fixed-epoch, and optimization-prefix-only
modes; a mode is reported only when its raw JSON output is present.

The completed matched-width audit is summarized in the main paper. The earlier
reduced-width diagnostic is retained below only to make the version boundary
auditable; it is not used for a primary claim.

\section{Sparse SocialEvo Boundary}
SocialEvo now has complete five-seed HRCSR, strict-RASP, all-source,
target-only T-GAT, and target-only GraphMixer artifacts for seeds 0, 1, 2, 3,
and 42. Direct per-seed transfer JSON files are authoritative because an
older resumed-run aggregate retained only seeds 3 and 42.

The SocialEvo runs use the audited skip-unsampleable sparse-negative policy.
Across the common processed split, validation retains 307,953 of 314,930
requested queries and test retains 310,119 of 314,924; no random fallback is
used.  Route, identity, hard, and soft paths share the same queries and
historical negatives.  The target-only summaries record the chronological
split, historical ranking, and 20 negatives but not per-query identifiers, so
they are contextual controls rather than proof of exact cross-process query-ID
equality.  The main paper consequently reports SocialEvo in a separate
five-seed sparse-domain table instead of pooling it with the dense panel.

\section{Contemporary Baseline Compatibility}
MiNT, BRIDGE, and GraphBridge are discussed in the main paper and audited in
\texttt{CONTEMPORARY\_BASELINE\_AUDIT.md}. Their released tasks or metrics do
not permit a direct historical-negative MRR comparison without changing the
scientific question; no cross-task numbers are imported.
